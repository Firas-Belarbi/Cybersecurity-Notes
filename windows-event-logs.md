# Windows Event Logs Overview

This document provides an overview of Windows event logs and their relevance in security operations.  
Event logs are a primary source of evidence for incident detection, analysis, and response.

---

## 1. Purpose of Event Logs
Windows event logs record important system, security, and application activities.  
They allow analysts to:

- Identify authentication failures
- Detect privilege escalation
- Monitor system configuration changes
- Investigate suspicious activity
- Track user and process behavior

---

## 2. Types of Event Logs

### 2.1 Security Log
Contains authentication and authorization events.  
Key categories:

- Logon attempts
- Privilege use
- Object access
- Account lockouts
- Kerberos events

Located at:
Event Viewer → Windows Logs → Security


### 2.2 System Log
Includes events generated by:
- Device drivers
- System services
- Hardware failures

Useful for diagnosing system-level issues.

### 2.3 Application Log
Logs generated by installed applications.  
May include:
- Crashes
- Errors
- Warnings
- Software-specific events

### 2.4 Other Logs
- **Setup**: OS installation and updates
- **Forwarded Events**: Logs collected from remote endpoints
- **Applications and Services Logs**: Detailed logs from Windows components (e.g., PowerShell)

---

## 3. Critical Events for Security Analysis

### 3.1 Logon Events (Event ID 4624 / 4625)
- 4624: Successful logon  
- 4625: Failed logon attempt  
Useful for detecting brute force or unauthorized access.

### 3.2 Account Lockout (Event ID 4740)
Triggered when a user account becomes locked.  
Often associated with:
- Password spraying
- Misconfigured services

### 3.3 Privilege Use (Event ID 4672)
Indicates that a user logged in with **special privileges**, such as:
- Administrator
- SYSTEM

Important for detecting privilege escalation.

### 3.4 User Account Management (4720–4726)
Tracks:
- User creation  
- Password changes  
- Deletions  
- Group membership modifications  

Important for insider threat investigations.

### 3.5 Kerberos Events
- 4768: TGT request  
- 4769: Service ticket request  
- 4771: Failed ticket request  
Useful for detecting:
- Pass-the-ticket  
- Golden Ticket  
- Kerberoasting

---

## 4. Logon Types (Important for SOC Analysts)

| Logon Type | Meaning                                      |
|-----------|-----------------------------------------------|
| 2         | Interactive (local physical machine)          |
| 3         | Network logon (file share, SMB)               |
| 4         | Batch (scheduled tasks)                       |
| 5         | Service logon                                  |
| 7         | Unlock screen                                  |
| 10        | Remote Desktop (RDP)                           |
| 11        | Cached logon                                   |

Logon type 10 is particularly important for detecting RDP activity.

---

## 5. Tools Used for Log Analysis

### Event Viewer
Built-in graphical tool for log examination.

### Wevtutil
Command-line tool for exporting logs:
wevtutil qe Security



### PowerShell Cmdlets
Common examples:
Get-EventLog -LogName Security
Get-WinEvent -LogName Security -MaxEvents 20


### SIEM Platforms
Used to aggregate logs across multiple systems:
- Splunk
- Elastic (ELK)
- Microsoft Sentinel
- QRadar

---

## 6. Relevance to SOC Operations
Understanding Windows event logs is essential for:

- Failed logon detection
- Suspicious RDP activity
- Privilege escalation alerts
- Lateral movement detection
- User behavior analysis
- Malware investigation

SOC analysts rely heavily on these logs to build detections and respond to incidents.

---

## 7. Summary
Windows event logs provide the visibility needed to detect, investigate, and respond to security incidents.  
Mastering these logs is one of the foundational skills for SOC and Blue Team roles.
